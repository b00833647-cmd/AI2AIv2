# Design — Academic README rewrite (research-software companion)

**Date:** 2026-05-15
**Topic:** Rewrite `README.md` as a scholarly research-software artifact that serves as the companion / replication-package front door for the negotiation-delegation study.
**Status:** approved (structure + content decisions), pending spec review.

## Context

The current `README.md` is engineering-oriented (quick start, deploy, env vars). The repo is the software + data artifact behind an ESSEC study of how humans delegate negotiation to AI agents. A human pilot (40 completers, 2×2, frozen snapshot `data/ai2ai-human-pilot-2026-05-15.db`) has been collected and two deterministic DOCX reports are generated by `scripts/analysis/`. The README should read as a scholarly artifact that foregrounds the experiment and points to a forthcoming study paper, while remaining a usable README.

## Goal

Replace `README.md` with a research-software-paper-style document, **companion-to-the-study-paper** framing: experiment foregrounded, replication-package framing, citation placeholder for the forthcoming paper. Operational install/deploy content is preserved but condensed and demoted.

## Non-goals / out of scope

- No code changes; no regeneration of reports; no new files (no `CITATION.cff` unless requested later).
- **No fabricated citations.** Related-work / literature references are not invented. References section contains only verifiable entries; an optional clearly-marked placeholder may be offered for the user to populate.
- `multi-agent-core/` internal docs, `CLAUDE.md`, and analysis specs are unchanged (CLAUDE.md drift may be addressed separately).

## Structure (final README section order)

1. **Title + descriptor + badges** — license, status; subtitle indicating it is the replication package / apparatus for the study.
2. **Abstract** (~150 words) — research question, apparatus, the 2×2 pilot, what the repo provides.
3. **Statement of need / contribution** — why a portable three-agent runtime + instrumented web study; what it enables for researchers.
4. **System architecture (as method)** — `multi-agent-core` model: participant agents + LLM orchestrator, the five-tool protocol, isolation/reproducibility invariants; existing ASCII diagram reframed in methods language.
5. **Experimental design** — conditions and the **2×2 (Mode × Role)**: Mode = AI-to-AI delegated (routes `/blx`, `/slx`) vs Human-to-AI direct chat (routes `/bhx`, `/shx`); Role = buyer vs seller. The locked Toyota Camry stimulus; the delegation manipulation; **opponent personalities** (easygoing / moderate / tough, buyer & seller variants, randomized uniformly per session); **measures** (9 survey DVs, behavioral telemetry, process metrics).
6. **Data & reproducibility** — SQLite data model (table summary), the frozen pilot snapshot, the deterministic Python pipeline → the two DOCX reports, regeneration commands.
7. **Ethics & data protection** — IRB/ESSEC consent; GDPR (no PII, hashed IPs, export/erase); free-text caveats.
8. **Installation & usage** — condensed quick-start + CLI + a compact deployment subsection pointing to `Dockerfile`/`fly.toml`/`railway.json`.
9. **Repository structure** — kept, lightly trimmed.
10. **Citation** — software BibTeX (Faraz Ghodratizadeh, ESSEC, 2026, MIT, DOI placeholder) **and** a forthcoming study-paper placeholder entry: authors **Faraz Ghodratizadeh & Amir Sepehri** (ESSEC), title/venue/year `TBD`.
11. **License & credits** — MIT © Faraz Ghodratizadeh; supervision acknowledgment to **Amir Sepehri (ESSEC)**; Wikimedia Commons photo attribution (CC BY-SA 4.0); Anthropic Claude / SDK.
12. **References** — minimal, verifiable only (Anthropic models/SDK, photo source). Optional placeholder *Related Work* only if the user supplies citations.

## Content decisions

- **Register:** formal academic prose, third person, precise/hedged claims; runnable commands retained verbatim.
- **Accuracy corrections (required).** The current README's description of behavior mapping is stale and must be corrected to match the code:
  - *Stale:* "behavior prompt mapped to a 7-dimensional signal vector by Claude (`mapUserBehavior`)"; opponent "randomized uniform over {−1, 0, +1} on each dimension."
  - *Actual* (per `multi-agent-core/STATE.md` 2026-05-06 note and `src/multi-agent/pack-builder.ts`): the LLM behavior-mapper was removed; the participant's behavior prompt and personal context are embedded **verbatim** into the agent's system prompt; the opponent is one of **three hand-written personalities** (easygoing / moderate / tough), each with buyer and seller variants, selected uniformly at random per session. The `mapped_signals_json` column persists as a legacy schema artifact and should be described as such if mentioned.
- **DV list** (from `scripts/analysis/human_pilot/data.py`): satisfaction, would_use_again, agent_represented, control, emot_pleasant, emot_anxious, effort_invested, engage_engaged, outfair_share.
- **Model facts:** default orchestrator `claude-opus-4-7`; participant model pinned in scenario packs (Claude Sonnet 4.x per project docs). Describe without over-specifying; note versions are pinned for reproducibility.
- **Citation metadata:** software author Faraz Ghodratizadeh (ESSEC), 2026, MIT, DOI placeholder; forthcoming paper authors Faraz Ghodratizadeh & Amir Sepehri (ESSEC).

## Acceptance criteria

- `README.md` follows the 12-section order above, in formal academic register.
- Every factual claim matches current code — in particular the behavior-prompt mechanism, opponent personalities, the 2×2 design, route→condition mapping, and the 9-DV list.
- All runnable commands from the current README are preserved (possibly relocated/condensed), not lost.
- Citation section includes a software BibTeX entry and a forthcoming-paper placeholder listing Faraz Ghodratizadeh & Amir Sepehri; acknowledgments credit Amir Sepehri as supervisor.
- No invented references; References lists only verifiable entries.
- No source code or non-README files modified.
