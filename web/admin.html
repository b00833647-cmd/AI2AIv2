What's in each export

Participants (wide) — columns

One row per participant. ~70 columns: identity, role, opponent personality, condition, demographics, device/browser, flags, free-text inputs, outcome, prices, turns, tokens, est cost, all 7 survey responses, dwell times, and event-type counts.

Full workbook — sheets
  • Participants — wide-format row per participant (~70 columns).
  • By Condition — aggregate stats for role × opponent personality.
  • Behavior Prompts — every revision the participant submitted.
  • Survey — Likert + free-text responses, one row per (participant × question).
  • Agent Log — all three agents (buyer, seller, orchestrator) interleaved chronologically with full timestamps. Each row carries: timestamp, agent, action, price (if proposal), target_participant (orchestrator request_turn), message-or-instruction, private thinking, rationale, model, latency, tokens in/out/total, raw JSON.
  • Buyer+Seller Turns — every participant turn with parsed action/price + raw tool_calls_json + tokens broken out + private thinking.
  • Orchestrator — every orchestrator decision with tool_name, target_participant, instruction, rationale, private thinking, tokens.
  • Agent Briefings — the system_prompt and brief_json each LLM was given at session start (reproducibility check).
  • Events — raw client telemetry events.
JSON bundle — structure

Hierarchical: each participant nests their behavior prompts, survey, events, full session with turns and orchestrator decisions. Plus pre-computed aggregates.

Database backup — what it is

A defragmented copy of the live SQLite file via VACUUM INTO. Bit-for-bit identical schema, immediately openable. Useful for: snapshot before risky operations, share with collaborators, run advanced SQL queries.
